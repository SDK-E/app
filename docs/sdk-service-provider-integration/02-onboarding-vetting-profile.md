# Round 2 — Onboarding, Vetting & Provider Profile

## Eligibility

Support individuals and registered independent businesses.

Architecture should not prevent later support for agencies or provider organizations.

## Application data

Collect:

- Identity/basic information
- Professional title
- Biography
- Skills and specialties
- CV/resume
- Portfolio/projects
- Years of experience
- Languages
- Expected rates
- Availability/capacity
- LinkedIn/GitHub/website
- Business/legal information
- VAT/tax information
- Preferred project types
- Working timezone / working hours

## Skill vetting

Initial skill vetting is based on portfolio/CV review.

No mandatory interview or technical assessment in the default workflow.

## Verification capabilities

Support:

- Identity verification
- Business registration verification
- VAT/tax verification
- Professional credentials
- Signed contractual documents
- Bank/payout ownership verification

Requirements should be policy-driven and configurable by provider type/service/risk.

## Profile completeness

Use:

- Minimum profile completeness requirement before submission/approval
- Visible completeness score

## Availability

Support:

- Available / unavailable
- Hours per week
- Available-from date
- Working schedule/timezone
- Calendar integration
- Planned absences
- Capacity per engagement
- Automatic capacity calculation

## Skills

Use:

- SDK-controlled skill catalogue
- Provider skill suggestions
- Hierarchical taxonomy
- Proficiency levels
- Verified skills

## Portfolio

Support:

- Native portfolio entries
- Images/files/videos
- External links and repositories
- Association with SDK projects where allowed
- Provider-controlled visibility

## Internal provider maturity

Use an internal quality/tier model.

Recommended lifecycle:

`New → Established → Preferred → Strategic`

Also maintain a dynamic reputation/performance score.

## Approval workflow

Support:

- Configurable review checklist
- Changes requested
- Internal notes
- Approval/rejection reasons
- Full audit history

## Post-approval behavior

Approval unlocks provider account and portal capabilities.

Commercially sensitive actions may remain gated until required contract, billing, business, and tax setup is complete.

## Service catalogue moderation

Every provider-created service requires SDK approval before publication.
