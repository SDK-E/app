# Round 4 — Engagement & Work Execution

## Engagement origins

Support engagement creation from:

- Accepted proposal
- Direct SDK assignment
- Existing client agreement
- Future service purchase
- Manual SDK creation

Every engagement has a permanent ID and audit history.

## Parties

Explicitly associate:

- Client
- SDK Enterprises
- Provider
- Responsible SDK manager

Multiple providers may work on one project, but provider commercial agreements should remain separate engagements.

## Engagement types

Support:

- Hourly
- Fixed price
- Milestone-based
- Retainer
- Day rate

## Engagement states

`Draft → Pending Setup → Pending Provider Acceptance → Pending Client Approval → Ready → Active → Completion Requested → Client Review → Completed → Closed`

Alternative states:

`On Hold / Cancelled / Terminated / Disputed`

## Terms

Store/version:

- Scope
- Responsibilities
- Dates
- Capacity
- Schedule
- Provider compensation
- Client pricing
- Currency
- Billing model
- Payment terms
- Notice/cancellation terms
- Confidentiality
- IP terms
- Special conditions
- Attachments

## Contract workflow

`Draft → Generated → Sent → Viewed → Signed → Active → Superseded/Terminated`

Support templates, provider agreements, engagement agreements, NDAs, amendments, client agreements, e-signature, signed-document storage, and audit history.

## Statement of Work

Structured SOW:

- Objectives
- In scope
- Out of scope
- Deliverables
- Acceptance criteria
- Dependencies
- Assumptions
- Timeline
- Milestones
- Constraints

## Milestones

Support:

- Deliverables
- Due date
- Provider compensation
- Client price
- Acceptance criteria
- Dependencies
- Attachments
- Assigned providers
- Review/revision workflow

States:

`Planned → Ready → In Progress → Submitted → Under Review → Changes Requested → Resubmitted → Approved → Completed`

Alternative: `Cancelled / Blocked`

## Tasks

Use lightweight tasks with:

- Assignee
- Due date
- Priority
- Status
- Milestone link
- Comments
- Attachments

Do not attempt to replace full project-management products.

## Deliverables

Support:

- Files
- URLs
- Repository/commit/PR
- Documents
- Designs
- Text
- Structured references

States:

`Draft → Submitted → Under Review → Changes Requested → Resubmitted → Accepted/Rejected`

Deliverable versions are preserved.

## Time tracking

Support:

- Timer
- Manual entries
- Engagement/milestone/task association
- Work description
- Editable entries before submission
- Future external time-tracker integration

## Timesheets

Raw time entries feed periodic timesheets.

`Draft → Submitted → Changes Requested → Approved/Rejected → Locked`

Client approval is configurable.

Approved timesheets may become invoiceable.

## Day-rate engagements

Support:

- Full day
- Half day
- Configurable day definition
- Work calendar
- Absence
- Approved day statements
- Monthly statements

## Retainers

Track:

- Period
- Included capacity
- Used capacity
- Remaining capacity
- Rollover rules
- Overage rules
- Provider compensation
- Client pricing

## Fixed-price work

Allow billing/work recognition based on:

- Entire project
- Milestones
- Deliverable acceptance
- Custom schedule

## Change control

Changes must be explicit and versioned.

A change request can affect:

- Scope
- Deliverables
- Dates
- Capacity
- Milestones
- Provider compensation
- Client pricing
- Engagement terms

States:

`Draft → Submitted → Impact Assessment → Awaiting Approvals → Approved → Applied`

Alternative: `Rejected / Cancelled`

## Communication

Engagement-specific threads for:

- General
- Milestones
- Deliverables
- Change requests
- Timesheets

Support mentions, attachments, internal SDK-only notes, notification preferences.

## Files

Central engagement file repository with versions and access controls.

## Calendar

Aggregate:

- Engagement dates
- Milestones
- Deadlines
- Interviews
- Availability
- Absence
- Meetings
- Contract deadlines

## Capacity calculation

`Total Capacity - Active Allocations - Approved Absence - Reserved Future Allocations = Available Capacity`

## Approval

Configurable:

`Provider → SDK Review → Optional Client Review → Accepted`

## Completion

Validate configurable completion requirements before closure.

## Closure

Closure may trigger:

- Lock work records
- Final timesheet
- Invoice eligibility
- Final client billing eligibility
- Performance review
- Reviews
- File archival
- Capacity release
- Reputation updates

## Termination

Support termination request, notice calculations, outstanding work, financial reconciliation, approval, and termination.

## Disputes

Disputes may attach to:

- Engagement
- Milestone
- Deliverable
- Timesheet
- Invoice
- Payment
