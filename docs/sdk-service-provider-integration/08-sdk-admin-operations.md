# Round 8 — SDK Admin & Operations

## Operating principle

The admin experience is built around:

**Queues, exceptions, decisions, ownership, and auditability**

not generic CRUD screens.

## Provider Operations

Support:

- Provider directory
- Provider 360° view
- Application review queue
- Verification queue
- Provider status controls
- Internal notes
- Tags/segments
- Compliance warnings
- Availability/capacity
- Service moderation
- Performance history
- Warnings
- Restrictions
- Suspension
- Offboarding

## Opportunity Operations

Support:

- Client request intake
- Opportunity creation
- Positions/roles
- Visibility control
- Eligibility preview
- Matching
- Ranked candidates
- Boost/suppress/exclude
- Invitations
- Proposal review
- Shortlists
- Interviews
- Selection
- Offers

## Engagement Operations

Support:

- Engagement overview
- Provider/client terms with permission separation
- Milestones
- Deliverables
- Timesheets
- Change requests
- Documents
- Communications
- Capacity
- Risks/issues
- Completion
- Termination
- Disputes

## Operational queues

Examples:

- Applications awaiting review
- Verification expiring
- Services awaiting approval
- Invitations awaiting response
- Proposals awaiting review
- Offers awaiting response
- Deliverables awaiting review
- Timesheets awaiting approval
- Provider invoices awaiting approval
- Providers at risk
- Overdue client invoices
- Open disputes
- Failed integrations

## 360° views

### Provider 360

Profile, compliance, capacity, services, proposals, engagements, financial relationship, performance, incidents, disputes, notes, audit.

### Client 360

Organization, contacts, opportunities, providers, engagements, billing, POs, satisfaction, issues, notes.

### Project 360

Client need, positions, providers, engagements, scope, progress, capacity, deliverables, financials, risks, documents, activity.

## Overrides

Manual overrides require:

- Permission
- Reason
- Actor
- Timestamp
- Previous value
- Resulting value

Sensitive overrides may require elevated approval.

## Bulk actions

Support controlled bulk operations with strong confirmation and audit logging.

## Saved views

Allow staff to save filtered operational views.

## Internal ownership

Applications, opportunities, engagements, support cases, and disputes can have owners and teams.

## Internal collaboration

Support mentions, internal comments, internal attachments, handoff, and activity logs.

## Permissions

Do not rely on one generic admin role.

Use capability-oriented authorization.

## Audit explorer

Searchable audit history across the provider ecosystem.
