# Round 11 — Notifications, Communications & Documents

## Notification architecture

Use a centralized event-driven notification system.

Separate:

- Domain event
- Notification intent
- Channel delivery
- Delivery result
- User preference

## Channels

Support:

- In-app
- Email
- Future push/mobile
- Future external communication integrations

## Notification preferences

Allow users to configure channels for non-critical notifications.

Critical legal/security/financial notifications may bypass optional preferences where appropriate.

## Notification categories

Examples:

- Application
- Verification
- Opportunity
- Invitation
- Proposal
- Interview
- Offer
- Engagement
- Deliverable
- Timesheet
- Change request
- Invoice
- Payment
- Compliance
- Review
- Dispute
- Security
- Support

## Delivery guarantees

Track:

- Queued
- Sent
- Delivered where provider supports it
- Failed
- Retry status

Avoid sending duplicate notifications for repeated event processing.

## Communications

Use contextual threads attached to entities instead of building a standalone messaging product first.

Thread contexts may include:

- Opportunity
- Proposal
- Engagement
- Milestone
- Deliverable
- Timesheet
- Change request
- Dispute
- Support case

## Visibility

Messages may be:

- Provider-visible
- Client-visible
- Provider + SDK
- Client + SDK
- SDK internal

Never mix internal notes with external messaging.

## Documents

Use a shared document/file service for:

- Provider application files
- CV
- Portfolio assets
- Verification evidence
- Contracts
- NDAs
- SOWs
- Amendments
- Deliverables
- Timesheet attachments
- Invoices
- Credit notes
- Expense receipts
- Payment evidence
- Tax documents
- Support/dispute evidence

## Document metadata

Track:

- Type
- Owner
- Related entity
- Visibility
- Version
- Uploaded/generated by
- Timestamp
- Integrity/hash where appropriate
- Retention classification
- Signed status where relevant

## Generated documents

Use templates with immutable snapshots once finalized/issued.

## E-signature

Abstract the signature provider.

Track signature workflow independently from vendor implementation.

## Versioning

Do not overwrite accepted/signed/issued documents.

## Retention

Retention rules should be configurable by document class and legal/business needs.
