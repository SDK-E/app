# Round 1 — Business Model

## Locked decisions

### Network model

Curated talent network.

Providers apply and must be approved before becoming part of the usable network.

### Provider offering model

Each provider has:

- Professional profile
- Skills
- Experience
- Availability
- Rates
- Portfolio
- Service catalogue

### Ways providers receive work

Support:

- Direct SDK assignment
- SDK invitation to opportunity
- Provider browsing of eligible opportunities
- Provider proposals
- Future recommendation / matching

### Provider visibility

Approved provider profiles are visible to authenticated clients.

### Commercial relationship

The provider bills SDK Enterprises.

SDK Enterprises separately bills the client according to the client agreement.

Support negotiated and engagement-specific pricing.

The domain must separately model:

- Provider compensation
- Client pricing
- SDK margin / spread

### Engagement models

Support:

- Hourly
- Fixed price
- Milestone based
- Retainer
- Day rate

### Approval model

Manual approval initially, with architecture capable of risk-based verification.

Provider lifecycle should support at least:

`Draft → Submitted → Under Review → Changes Requested → Approved → Suspended → Rejected → Archived`

Approval must not be represented by a single boolean.
