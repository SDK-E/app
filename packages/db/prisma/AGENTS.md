# Prisma and database changes

These instructions supplement the repository-level `AGENTS.md` for `prisma/**`.

- Read the relevant architecture and ADR documents and use the
  `prisma-next-migrations` skill before changing the schema or migrations.
- Use Prisma for application data access. Migration SQL generated by Prisma may be
  reviewed and committed; do not introduce application-side raw SQL.
- Prefer additive, data-preserving migrations. Explicitly handle existing rows before
  adding required columns or uniqueness constraints.
- Inspect and state the resolved database target before applying a migration.
- Never apply migrations to a remote, shared, staging, or production-like database
  without explicit authorization for that exact target.
- Review every migration statement, run the migration against an authorized disposable
  or local PostgreSQL database, then regenerate Prisma and run `pnpm run verify`.
